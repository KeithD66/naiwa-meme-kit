# 多角色生态与复用方法

最后核验：2026-10-29。角色 ID 与名称消歧见 `characters.md`；候选来源和固定版本见
`research/ecosystem-resources.json`。下述编剧位置是创作建议，不是官方人物关系。

| 图鉴／交互站 | 艺术馆、共创图鉴、游戏可继续追原媒体 | SVG fallback、程序绘图与合成音效能冒充原素材 |

已有可复用的单角色素材与索引，但本次没有核实一个身份、声音、许可全齐的统一全角色包。
本库负责把分散来源连接起来，同时保留未知项。

## 一条视频里的分工

先用 1 主角 + 1 配角的短镜头检查身份，再加人。

| 编剧位置 | 可选角色 | 节奏用法 | 前提 |
|---|---|---|---|
| 雷霆主位 | 奶蛙 | 战斗脸、舞步、强变焦、捧腹笑 | 同源参考与现成动作来源已选定 |
| 安静对照 | 噜噜 | 切到已有发呆／等待动作 | 取现成画面，不重造人物 |
| 短反应位 | 奶蛋 | 已有呆立／叉腰配短语音 | 保留 andi 与奶蛋的来源关联 |
| 吐槽回击 | 胖袋鼠 | 现成表情配已核对口癖 | 具体版本与录音匹配 |
| 梗音触发 | 牛来 | 声音提示后给原片参考镜头 | 不拿唐牛或普通牛替代 |
| 待解锁 | 奶粉、唐牛及其它未锁定版本 | 来源说明占位，不生成形象 | 先补所需身份与参考 |

刺激来自可辨认的变化：完整动作 → 突然切脸 → 断乐 → 反应镜头 → 笑声回击。
一个声音对应一个反应，不在每个镜头同时塞满多个人物、口癖和 BGM。

## 多人同框的身份隔离

1. 每个角色独立写检索 ID、所选版本、来源 URL 与实际本地路径。
2. 分别上传各自现成参考，固定标成 A／B，并在镜头卡写清左右位置。
3. 先核单角色脸、体型和动作，再进入多人镜头。
4. 动作提示词明确 A 的颜色、脸、耳鼻、肚皮、手脚和服饰归 A；B 同理，不相互混合。
5. 两套素材风格不一致时，先用切镜分别展示；不让模型为“统一风格”发明折中版角色。
6. 转身必须有同版本的侧／背参考；没有就缩小动作和机位变化，不自由补全。

每位配角最低记录：

```yaml
character_id: capylulu
display_name: 水豚噜噜
variant_id: 所选现成来源与版本
identity_status: unresolved
reference_asset_ids: []
source_urls: []
view_coverage: []
audio_cue_ids: []
must_preserve: []
must_not_confuse_with: []
media_license_status: unverified
generation_ready: false
```

`reference_asset_ids` 必须指向已取得且实际查看的素材，`audio_cue_ids` 没有就留空。
外貌约束从选定图提取，不能凭名字补齐。一个角色未识别不应阻止其他来源整理。

## 容易混淆的边

- 奶粉角色 ↔ 奶粉粉丝称呼：已有双义证据，按具体语境选分支。
- 奶鼠 ↔ 美团老鼠：分别查作者、造型、原声，不因“鼠”字合并。
- 唐牛 ↔ 牛来：不做无证据的同音纠正。
- 豆奶 ↔ 豆包：组合昵称、独立衍生角色、官方助手可能不同。
- 奶蛙 ↔ 奶龙：看实际参考，不能只凭文件名中的 nailong 决定身份。

## 新角色入库

至少取得可识别身份的原图／原片来源、作者或发布账号、素材类型、获取状态与许可。
把“搜索标题命中”“页面可读”“文件下载”“已查看”“可供生成”分别记录；
后者不由前者自动推出。新来源先入候选，不覆盖已选角色版本。

导入公开项目时只取必要媒体和元数据，不运行桌宠安装器或站点脚本；
不把自动合成音效、SVG 兜底或文字重造形象当现成原梗。
发布前仍逐项核对角色、媒体、音轨与平台条件，代码开源不替代媒体授权。
